# V7学生交付规范

## 基准与用途

采用示例学生V7学生版的栏目、顺序和表达。它是可复用的交付格式，不是其他学生的经历、学校或职业方向样本，也不限制后续方案更新。运行时以配套模板为基准，不依赖示例学生原文件存在。

学生应能读懂：每个项目准备讲什么，为什么选这些经历，已经体现哪些能力，进一步学习什么，以及希望如何应用。交付是中文申请规划，不是PS正文或内部写作指令。

## 固定结构

标题、学生姓名之后，先给六列组合总览，再按相同项目顺序给九字段叙事卡。列名、字段名及顺序以 `assets/student-matrix.md` 为准；不额外保留旧字段或增加审计附录。

| 九字段 | 内容职责 |
|---|---|
| 申请方向 | 本项目聚焦的专业或应用领域 |
| 核心叙事主线 | 已有准备、具体专业问题、学习必要性的整体联系；核心问题自然融入其中 |
| 文章展开顺序 | 读者依次看到什么，经历、学习需求和项目选择怎样衔接；包含开头作用，不预设段落数 |
| 论证路径 | 为什么这些经历能引出认识、学习需求与未来应用；解释因果，不重复一遍文章目录 |
| 核心素材及其作用 | 真实经历片段、本人行动及其体现的能力；每项素材怎样支撑主线 |
| 重点能力 | 已有事实能支持的能力，避免无依据的自我评价 |
| 需要通过学业补足的能力 | 承接已有准备、具体尚待发展的能力，避免反复强调个人不足 |
| 建议职业方向 | 与经历及项目相关、有适度发展顺序的未来工作建议 |
| 项目课程与学习需求的对应 | 最相关的2–3项已核实资源如何回应需求；不必为凑数量增加课程 |

总览每格用短语或简短一句话，细节留在卡片。卡片每项以一段直接说明为主，允许箭头表示顺序或因果；避免多层列表、动作核销表以及逐字重复总览。

## 旧版到V7的转换

| 旧版表达或字段 | V7处理 |
|---|---|
| 一句话核心命题（已有认识/能力 + 未解决问题 + 目标专业必要性）、核心问题或判断 | 合并为“核心叙事主线”，把括号内的内部提示转成自然叙述 |
| 开头切入点及其因果作用、预期段落功能 | 合并为“文章展开顺序”，保留怎样展开及怎样衔接 |
| 因果路径 | 改为“论证路径”，解释已有准备到学习需求的联系 |
| 必须使用的证据及各自职责 | 改为“核心素材及其作用”，讲清行动和能力，不向学生发写作命令 |
| 需要补足的能力、职业目标、Why Program 对接资源 | 分别改为“需要通过学业补足的能力”“建议职业方向”“项目课程与学习需求的对应” |
| “写作者构建的未来意向” | “毕业初期希望……，随后……”；通过字段名“建议职业方向”表达建议性质 |
| “未证明他决定价格或带来增长” | 按实际角色写“参与测算”“提供支持”，把更高层判断放到学习需求，不另列免责声明 |
| “不得虚构”“不与另一篇混用”“实际结构签名待回填” | 不进入学生版；有效方案信息归入相应九字段，来源和执行约束保留在工作矩阵 |

## 表达与事实边界

- 用“具体做了什么→说明什么准备→希望进一步学什么”解释能力，避免仅列“分析力、领导力、国际视野”。不要求每张卡套同一种开头或论证顺序。
- 保留真实支持角色、导师指导和成果性质。支持不改成独立决策，报表产物不改成已验证效率提升，竞赛认可不改成经营收入。边界通过准确动词及学习方向自然呈现。
- 没有材料支撑的论文结论、历史动机或商业决策不进入交付。能安全省略的细节直接省略，不给学生留“待补充”占位；基本事实不足以支撑主线时按skill阻塞规则处理。
- 职业方向可以主动提出，但用希望、计划等未来语气；范围与可迁移能力及项目相容，避免无依据地锁死到某一雇主、产品或过窄岗位，也不泛化为空洞愿景。
- 课程与资源名称附对应官方链接。未确认的资源先不具名，必要核验限制放交付说明，不放核验日志。

## 不进入学生交付的内容

内部路径、来源检索过程、事实缺口清单、写作者禁令、主动舍弃清单、经历复用边界表、语义增量、模板族、核销记录、净化交接包、模型思考、评分、审稿轮次、相似度数值、Pass/Revise状态、正文待生成或待回填状态。不得藏在HTML注释、折叠块或附录里。

上述信息仍可保留在工作矩阵与内部记录，学生版只保留可直接阅读的规划。模板 `{{...}}` 全部替换；发布、审查通过与学生确认分别记录，不能互相替代。

## 后续同步

矩阵生成或同步任务遇到后续已采用的正文变化时，以可追溯的最新选择更新受影响卡片及总览，再局部同步工作矩阵；不沿用已被用户否定的辅助经历或旧职业方向。正文仅润色、不改变叙事内容时可保留原矩阵。不要从内部候选轮次或文件时间推断采用状态。
