# 全局审查规则

## 高优先级错误

出现以下问题时，审查状态应为 `Blocked` 或 `Needs Fix`：

- 编造学生资料中不存在的课程、成绩、学校、项目、奖项、时间、数据。
- 混用不同学生或不同推荐人的素材。
- 推荐信把推荐人口吻写成学生自述。
- PS 输出成分点提纲，而不是中文连贯文章。
- 简历虚构量化成果或职责。
- Resume-Experience 将 Course_Info 中缺乏具体行动、方法或结果的项目强行写成正文经历。
- 文件输出为非 `.md` 格式。

## 推荐信常见坑

- 两封推荐信开头都长篇介绍推荐人，显得模板化。
- 两封信使用同一个核心例证或同一组能力标签。
- 固定段直接复制 reference 原句。
- 可变段没有绑定该推荐人的课程素材。
- 目标项目未知时编造学校或专业匹配信息。

## PS 常见坑

- 没有按应届生顺序组织：本科专业原因、本科经历、职业规划、硕士专业/学校原因。
- 把所有素材都塞进文章，导致主线松散。
- 时间线前后错乱。
- 引入资料中没有的教授、课程、实验室或职业目标。

## 简历常见坑

- bullet 写成长段叙事。
- 动词弱，结果和方法不清楚。
- 为了显得强而添加没有来源的数字。
- 经历排序没有服务申请专业。

## Resume-Experience 常见坑

- 把只有标题或空模板字段的 Course_Info 项目写进正文。
- 为了套格式编造角色、时间、工具、模型、数据规模或成果。
- 直接沿用参考简历中的项目类型、公司、成果或表达。
- 缺少 `未纳入项目`，导致资料不足的项目没有被记录。
- 缺少 `资料依据`，后续无法追溯 bullet 来源。
