# 英文升学申请简历格式

适用于不同申请人。默认流程为：学生资料标准化 → 全量 Resume-Experience 经历库 → 按用途筛选 → 按统一规范生成简历 → 审查与发布。经历库沉淀事实和可复用英文表达，完整简历负责取舍与呈现。不得直接跳过经历库，从零散资料拼出正式简历。

## 使用方式

先读取 [完整格式规范](references/format-standard.md)。该文件包含提取依据、页面参数、逐行职责、原稿完整段落映射及原稿与建议改进的区别。原 `.doc` 不必在每次调用时重新读取；如用户提供新参考或要求像素级复刻，再检查其原件。

区分任务范围：

- 仅说明、沉淀或检查格式：输出 Markdown 规范或问题清单，不改写学生经历，不启动文书写作流程。
- 套用现有简历：保留已确认内容，调整层级和格式；指出缺失字段，不从参考样例移植事实。
- 从学生资料生成或实质修改申请简历：执行下述两阶段流程。在 Application-MSC 内与 `resume-application-pipeline` 衔接，并遵循当地 AGENTS.md 的资料标准化、偏好、看板、版本和审查流程。此 skill 提供经历库前置规则与格式，不替代内容审查。

用户指定的格式和输出要求优先。没有单独授权 Word 输出时，正式内容保留 Markdown，并给出可执行的排版参数；不能声称 Markdown 已保存 Word 的字号和行距。在 Application-MSC 中依当地规则保存 `.md`，不因调用本 skill 自动导出 Word 文件。其他环境明确要求 Word 时使用可用的 documents 技能与运行依赖，并完成渲染检查。

## 阶段一：先生成 Resume-Experience 经历库

读取学生偏好、任务看板和资料完整性检查，确认 Markdown 标准化后，汇总 `Basic_Info/`、`Resume/`、`Course_Info/`、相关 `Additional_Documents/` 与用户明确补充。原始资料中提及的附件必须读取对应 Markdown。学校、学位、GPA、课程、联系方式等放入基础信息区，不改写为经历 bullet。

本 skill 中 Resume-Experience 是广义经历库，涵盖有证据的实习/工作、科研、课程/工程项目、竞赛与活动，不仅是课程项目。现有 `resume-experience-writer` 负责 Course_Info 项目子集；调用时保留其全量转化与审查规则。其他经历由本流程根据其各自资料整理，不能假定该专项 skill 已经覆盖实习或活动。

先检查最新已通过审查的经历库。只有来源仍一致、资料范围完整、用户未补充新事实时才直接复用；否则保留旧版本，预留一个新的经历库正式版本。合并重复来源中的同一经历，不将同一项目在不同材料中重复计数。

为每条经历建立稳定 ID（如 EXP-001），整理以下字段：

- 经历分类、名称、机构/课程、角色、日期；缺失字段明确记录，不能猜测。
- 经核验的背景、个人职责、具体行动、方法/工具、结果或验证；区分个人贡献与团队成果。
- 可复用的英文动作 bullet，通常 2–4 条；有充分证据时可保留更多独立素材，不为固定条数添加空话。
- 每个关键事实及 bullet 的来源路径/定位，供审查与简历回溯。
- 缺失信息、冲突、不可使用事实。没有足够个人行动的经历列入“未纳入经历”，说明原因。

经历库全量整理可转化经历，不按当前目标专业删掉项目或实习。此阶段不受最终一页限制，不强制套用最终简历字号、栏目顺序和条数。

建议经历库结构：

```markdown
# 学生名 Resume Experience Vn
## 基础信息
[已确认的教育、联系信息、技能等，附来源]
## Internship / Work Experience
### EXP-001 经历名称
[机构、角色、日期]
[可复用英文 bullets]
[事实来源与待确认项]
## Research Experience
## Project / Competition Experience
## Activity Experience
## 未纳入经历
## 资料依据
```

仅建立有资料的栏目。课程项目继续保留“未纳入项目”记录；广义经历库可另设“未纳入经历”。不将待确认信息写成英文既成事实。运行 `application-review` 的 Resume-Experience 审查，并遵循工作区要求完成其适用门禁。只有通过的库才能成为下一阶段的正文依据；部分经历有缺失时，可审查并使用已核验子集，但必须记录排除项。

## 阶段二：根据经历库生成完整简历

先确认用途或目标专业，再读取当前已通过审查的经历库和 [格式规范](references/format-standard.md)。不得在排版阶段另造事实；需要新增经历时，先更新经历库、审查，再回到简历。

在内部建立选择表：`经历 ID → 使用的 bullet → 目标能力 → 保留/压缩/舍弃 → 事实来源`。按用途、证据强度、个人贡献和篇幅选择经历。可以压缩、重排或翻译润色经历库中的表达，但数字、角色、因果和结果边界必须一致。经历库中未选中的条目保持完整，不因这份简历取舍而删除。

教育、联系方式与技能使用经历库基础信息区；必要时回查原始 Markdown 核验。最终简历不显示内部 ID、资料依据、待确认问题和选择表。按下述格式安排姓名、教育、实习、科研、项目与其他信息；没有材料的栏目省略，栏目取舍不以参考简历是否有该栏目为唯一依据。

在 Application-MSC 内，通过 `resume-application-pipeline` 调用 `resume-writer`（定向时结合 `targeted-one-page-resume-writer`），将已通过的广义经历库作为经历来源，并明确使用本 skill 的格式参数。保持先 `application-review`、后 `resume-quality-review` 的门禁顺序。遇到事实问题先修正经历库，再同步简历；只有表达或取舍问题可仅修简历。格式规范不覆盖用户要求和事实门禁。

经历库与最终简历是两个独立文书 key：分别扫描并预留各自一个 Vn，内部修改使用任务临时目录中的 Rn，不能把两类文书共用一个版本计数。新生成的经历库保存到 `Resume_Experience/`，最终简历保存到 `Resume/`，均为 Markdown；复用已有库时只新增简历版本。全部适用审查通过后，更新看板、审查记录和版本索引。向用户交付最终简历，并在本次新建经历库时提供其正式版本链接，不展示内部过程文件。

## 默认格式参数

| 对象 | 设置 |
| --- | --- |
| 页面 | A4 纵向、单栏；左右边距 1.27 cm，上下约 0.67 cm |
| 字体、颜色 | Times New Roman，黑色 |
| 姓名 | 16 pt，加粗，居中，独立一段 |
| 栏目 | 11 pt，全大写、加粗、单下划线，左对齐 |
| 学校标题 | 10.5 pt；学校和地点加粗，日期常规 |
| 实习标题 | 10 pt；公司与岗位加粗，日期常规 |
| 研究/项目标题 | 10 pt；名称加粗，角色或性质斜体且不加粗 |
| 学位行 | 10.5 pt，斜体 |
| 其他正文 | 10.5 pt，常规，两端对齐 |
| 行距 | 固定 14 pt；姓名若裁切则单独调为至少 18 pt，并说明差异 |
| 段间距 | 普通段前后 0 pt；学校标题前后各 3 pt；后续经历标题前 4 pt、后 1 pt |
| 正文缩进 | 左缩进约 0.74 cm，首行与续行文字对齐 |
| 日期对齐 | 使用正文右边界的右对齐制表位，约 18.46 cm；不填充连续空格 |

默认按核对过的参考渲染使用无符号缩进正文，显式清除旧列表编号。用户要圆点列表时，使用标准圆点和悬挂缩进，不继承 Wingdings 隐藏符号。原稿有列表元数据但转换渲染未显示圆点，因此不得宣称原件确定没有项目符号。

栏目下划线默认只覆盖标题文字。原稿通过给标题后的空格加下划线产生长线效果；不复制这种空格技巧。用户要求通栏线时用段落下边框，并标为有意调整。

## 逐行内容与排序

“行”指逻辑段落，长内容自动换行，不强制每条占一条视觉行。

1. 姓名。原稿无联系行；其他简历确需电话、邮箱时，只使用已确认信息另加联系行。
2. EDUCATION：学校与地点＋右侧日期 → 学位、专业及预计毕业时间 → GPA → 相关课程。
3. INTERNSHIP EXPERIENCE：公司与岗位＋右侧日期 → 独立描述段落。多条实习按日期倒序。
4. RESEARCH EXPERIENCE：研究名称＋角色/性质 → 独立描述段落。
5. PROJECT EXPERIENCE：项目名称＋角色/性质 → 独立描述段落。
6. OTHER：分类标签＋冒号＋具体技能或其他有依据的信息。

参考稿每段经历有四条描述，但数量不是必填约束。描述先交代主要工作，再选择有证据的关键行动、方法、限制、结果或验证；不让每段机械填满同一套句式。研究和项目仅在有确切日期时加日期；有多个条目时默认倒序，允许按用户指定的相关性排序。没有真实材料的栏目省略。

学位、成绩、课程、日期、角色、技能与成果均来自目标学生。参考稿的 `Individual Project` 与团队描述存在需核实之处，绝不能照搬。自我评价不是必填项。英文日期统一采用 `Mon. YYYY – Mon. YYYY` 或 `Mon. YYYY – Present`，技能分隔用英文逗号。

## 执行与验收

- 先划分姓名、栏目、学校标题、经历标题、学位和正文六类样式，再应用参数。不能直接依赖参考文件 Normal 的 12 pt 默认字号。
- 标题与首条描述保持同页。长标题与日期冲突时，将角色移至下一逻辑行，保留日期可读性。
- 保持一页紧凑风格，但不为凑一页缩小正文到 10.5 pt 以下；优先压缩重复内容或按用户目标选择材料，任何删改不得改变事实。
- 实际 Word 排版后核对每页：日期列、姓名裁切、字体替代、列表符号、续行缩进、末尾空页和标题孤立。未渲染时明确版式尚未视觉验证。
- 仅格式检查不自动修改学生偏好、版本索引或历史；实际生成正式学生简历时依工作区规定维护这些记录。

## 阻塞条件

经历库未通过审查时，不进入最终简历生成。关键身份或经历事实缺失、角色与正文冲突时，不自行补齐，列明待确认项；可继续整理其他有依据的经历和格式。转换或渲染失败时保留原件与已有 Markdown，并说明无法验证的参数，不将推测标为原稿设置。

## 最小输出

从资料生成简历时，最小输出为通过审查的 Resume-Experience 经历库（新建或明确复用的正式版本）与根据该库生成的新简历 Markdown。仅格式任务则交付格式规范或问题清单。附必要的排版参数与未验证项。只有用户要求且环境规则允许时交付 Word，并先完成渲染检查。保留原始附件及已有正式版本。
