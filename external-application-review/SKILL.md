# External Application Review

## 核心原则

以第一次看到成稿的外部读者身份审稿。审稿人与写作者必须上下文隔离；只提交意见，不直接修改正文。目标是发现有实质收益的问题，不是证明文章永远还能润色。

## 强制隔离

每一轮内容审稿都必须启动一个全新 Subagent，并且不继承当前对话、上一轮审稿、写作或修改上下文（例如使用 `fork_context: false` 或平台等价能力）。默认 `single-draft` 模式只传入经过净化的审稿输入包：

1. 本 skill 路径与待审成稿路径。
2. 文书类型、目标项目或用途。
3. 用户明确给出的字数、题目或项目要求。
4. 可选的最小项目信息摘要；只包含判断项目匹配所需的课程、培养方式和目标要求。
5. 当前初始单篇审查轮次 `C1` 至 `C5`，或组合修改后的补充单篇复核轮次 `S1` 至 `S5`。

不得传入写作过程、作者解释、旧候选稿、上一轮得分、上一轮审查全文、修改过程、既有审查结论、主 Agent 的评价或预期答案。Subagent 不得读取其他学生目录、`Review_History/`、`Revision_History/`、`Review_Memory/`、写作 skill 或修改 skill。每一轮都必须基于当前候选稿重新独立判断，不能被“上一轮已经改过”锚定。

PS 的 `portfolio-differentiation` 模式是唯一例外。该模式必须由另一个全新隔离 Subagent 执行，只允许传入：

1. 当前候选稿。
2. `Student_Profile/PS_申请组合叙事矩阵.md`。
3. 同一学生其他申请目标各自最新的正式 PS；同一目标不得传入多个历史版本。
4. 相似度工具报告。

组合模式另须注明独立的当前轮次 `P1` 至 `P5`。即使单篇在 `C5` 才通过，仍必须执行 `P1`；组合轮次不占用单篇轮次。

该模式仍不得读取写作过程、事实资料、学生反馈和其他学生文件。它只判断跨申请叙事差异，不重新做事实审查。

调用提示必须明确写明“你是已隔离的最终审稿人”。收到这一标记的 Subagent 直接执行本 skill，禁止再次派生审稿 Subagent。只有仍处于原写作上下文的主控 Agent 才负责启动隔离 Subagent。

如果平台无法创建隔离 Subagent，停止并报告 `Blocked`；不得由原写作者假装独立审稿。

## 过程文档隔离

正式发布前，所有内容审稿输入包、`C1`–`C5`、`P1`–`P5`、`S1`–`S5` 报告、建议采纳表、修改交接包和验收清单都只能保存在任务专用临时目录。它们不得进入 `External_Review_History/`、`Review_History/`、`Revision_History/`、学生正式输出目录或版本索引。

正式目录只保存最终通过候选稿对应的一份内容审稿报告。若初始单篇 `C5`、组合修改后的补充单篇 `S5` 或组合 `P5` 到达各自上限仍未通过，只在 `Application_System/reports/` 保存一份不含中间候选全文的 Failure Report，内部过程文件仍不得进入正式目录。

## 审查边界

- 审查结构、内容取舍、逻辑、个性化、说服力、目标适配、读者记忆点、重复和模板/AI 痕迹。
- 不重复承担 `application-review` 的完整事实核查、版本检查和素材溯源。
- 可以标记“疑似需要核实”，但没有资料时不得断言事实错误。
- 不得要求补写资料中未提供的新经历、数字、课程、领导行为、冲突、成果或项目细节。
- 如果某项改善依赖新事实，标为 `Needs Confirmation`，而不是 `Must Fix`。
- 不因纯个人措辞偏好判定必须修改。

审查前读取 [独立内容审稿规则.md](references/独立内容审稿规则.md)。审查 Personal Statement / SOP 时还必须完整读取 [个人陈述五维质量标准.md](references/个人陈述五维质量标准.md) 作为写作质量边界，并读取 [个人陈述八维评分与校准标准.md](references/个人陈述八维评分与校准标准.md) 完成八维量化审稿。第八维“跨申请结构独立性与相似度”必须基于同一学生所有相关 PS 的全文、段落功能签名和结构风险证据判断，不能用词面相似度或单篇评分替代。

## 执行流程

1. 确认 `review_scope` 为 `single-draft` 或 `portfolio-differentiation`。
2. `single-draft` 只读成稿和允许提供的最小任务信息。
3. `single-draft` 先完成无背景的读者盲审，再完成目标适配审查。
4. `portfolio-differentiation` 先为每篇 PS 抽取段落功能签名和结构签名，再比较核心命题、因果路径、素材取舍、经历职责、能力缺口位置、职业目标生成路径和结尾方式；随后对跨稿复用的每项经历做全文段落级审计，并完成第八维评分。不因共享硬事实自动判错，也不得因低词面相似度跳过结构同构检查。
5. 对每条建议标注优先级、定位、影响、修改方向和事实边界。
6. 明确列出 `Do Not Change`，保护有效内容。
7. 按下方“审稿人与主 Agent 交接协议”输出报告，不修改成稿、不创建新的正式版本。

PS `single-draft` 必须依次执行：内容论证、结构、段落功能、语言表达，不能先进行逐句润色。

## PS 信息组织与表达复核

在已有“逻辑结构”和“语言表达”维度内执行，不增加评分维度、轮次或词频门禁。审稿依据是当前正文及本 skill 的审查标准，不读取写作/修改 skill、语言修改过程或上一轮诊断。

本 skill 与其参考标准、报告示例中的“能力缺口”按具体学习需求理解，包括深化、迁移、整合或补足能力；矩阵/结构签名保留原字段名，审计实际需求及其位置，不要求一定写不足。报告示例中的链条不得作为每段必填模板。

- 单篇必须通读完整正文，检查各段主句骨架、主从安排、信息焦点、具体对象承接、长短句职责、入口与收尾。即使句句信息不同，持续以 I + 行动/感悟/hope 平铺也可能掩盖重点、削弱节奏；不能只查重复词或首尾。检查是否多次用经历概括词接“理解加深/兴趣增强/想读硕士”，以及只加句首状语却未改变骨架的情况。
- 将这种重复与有效指代、必要术语、连续真实行动和有意平行结构区分开。I、These、which、简单句或某类从句本身不构成问题；不以复杂句数量、句长变化或降低 I 频率加分。
- 全文丰富度以信息关系是否清楚、重点是否突出和阅读节奏是否自然判断，不以复杂句数量判优。若跨段同一骨架使背景、行动、判断和愿望长期平铺，且能用现有内容安全改善，应列 `P1 / Should Fix`，不能因语法正确、每句有新信息或简单句可保留而一律降为 Optional；少量有功能的平行表达不构成该问题。
- 句法重复影响表达时使用现有 `PS-LANG` ID；信息层级、论证职责或结论重复使用 `PS-STRUCT` ID。同一根因可关联两个维度，但不得拆成多个重复处罚项。
- 每条建议必须给出具体定位、最短引文、重复的句法骨架或信息功能、读者受到的实际影响和可用现有文本完成的修改动作。全文问题应把范围写为“全文”，同时给出跨段证据，验收检查主从层级、承接和节奏，不能只要求替换 I hope 或减少 I。纯个人措辞偏好为 Optional；严重性仍按现有 P0/P1/P2 标准判断。
- 检查建议会否凭空增加行动、结果、时间先后、因果、失败或顿悟。缺乏事实依据时不得用更具体的虚构认识替代空泛反思；可以建议删减，确需新事实才标 Needs Confirmation。
- 深造动机可以来自成果深化、方法迁移、新场景应用、能力整合、职业延伸或未解问题。不能仅因全文没有“尝试失败—发现不足”、每段没有能力缺口或未采用固定顺序而扣分；必须判断学习需求与项目资源是否有具体联系。
- 组合模式在既有四层审计中比较实际信息入口、句式承担的动作及论证路径，避免以开头类别名称相同直接判错；也不得以更换句首单词或类别标签判定差异化。

`single-draft` 报告须包含简短“全文表达覆盖表”，每段一行：段落职责｜主要句法与信息关系｜入口/收尾及节奏｜保留或问题 ID。即使 Pass 也须覆盖每段，表格从当前稿提取，不读取写作者的诊断。经历主体、Why Program 和职业规划均须检查；无需逐句改写或为每段硬找问题。

## PS 时间表达的内容检查

完整文章默认不以具体个人年月和预计毕业信息堆履历；需要时间定位时可用有依据的学业阶段或事件语境，不要求每项经历都有年级。检查是否反复以 During my ... year 开段、是否删日期后造成先后/完成状态不清、跨学年叙述是否自相矛盾。正式竞赛名称、数据年份、必要时长或明确要求的日期不按冗余处理；学校/专业信息也不一律删除。

本内容盲审不读取入学资料、校历、写作者时间映射或写作/修改 Skill，不凭正文倒推年级。换算真实性由 application-review 负责；无法核实仅标疑似风险并请主控做事实复核，不虚构正确年级。基于当前全文确有的重复/歧义分别沿用 PS-LANG / PS-STRUCT，按实际影响分级，不新增评分维度或 C/P/S 次数。

## 优先级与状态

| 标签 | 用法 |
|---|---|
| `Must Fix` | 有明确文本证据的结构断裂、核心论证缺失、严重重复或自相矛盾 |
| `Should Fix` | 修改有清晰收益，且能用现有文本安全完成 |
| `Optional` | 合理但主观的风格选择，不应触发自动改稿 |
| `Needs Confirmation` | 需要新增或确认事实；不得自动写入正文 |
| `Do Not Change` | 已有效且应在修稿中保留的内容 |

PS `single-draft` 报告状态只能是：

- `single-draft` 的 `Pass`：前七个单篇维度平均分不低于 `8.5`，无 `P0 / Must Fix`，且无值得生成新候选稿的 `P1 / Should Fix`。第八维在没有组合输入时标为 `N/A`，不把跨稿问题伪装成单篇问题。
- `portfolio-differentiation` 的 `Pass`：矩阵四层全部 `Pass`，第八维得分不低于 `8.5`，无 `P0 / Must Fix`，且无值得生成新候选稿的 `P1 / Should Fix`。
- `Revise`：单篇前七维平均分低于 `8.5`，或组合第八维低于 `8.5`，或至少一项 P0/P1 可用现有内容安全处理。
- `Blocked`：无法获得隔离环境、无法读取成稿，或所有关键改善都依赖待确认信息。

`portfolio-differentiation` 不重复计算前七维单篇平均分，但必须新增并明确报告第八维得分；第八维不是“低词面相似度”检查，而是全文结构独立性门禁。

## 报告格式

执行 `C1-C5`、`P1-P5` 或 `S1-S5` 时，报告必须先保存到审稿输入包指定的任务专用临时路径，不得由隔离审稿人直接写入正式目录。只有最终 `Pass` 后，主控 Agent 才将该轮报告整理为一份正式报告，保存到 `External_Review_History/文书类型-目标-Vn-独立内容审稿.md`。文件名不得添加日期前缀；日期写入 frontmatter。正式报告可以在 frontmatter 中记录实际通过的内部轮次，但文件名只使用本次预留的正式 `Vn`，不得因内部轮次生成多个正式版本号。frontmatter 至少包含：

```yaml
---
student: 学生名
doc_type: Personal-Statement
draft_path: 相对路径
version: V1
internal_iteration: R1
content_review_round: C1
status: Pass
average_score: 8.7
review_mode: isolated-subagent
review_scope: single-draft
must_fix_count: 0
should_fix_count: 0
needs_confirmation_count: 0
review_time: YYYY-MM-DD HH:MM:SS
---
```

最终报告按实际经历增补 `portfolio_review_round: Pn`，以及在组合修改后确实执行过补充单篇复核时增补 `supplemental_single_review_round: Sn`；未执行的轮次不得填写。

Personal Statement `single-draft` 报告正文依次写：总体评价、八维评分（第八维无组合输入时标为 `N/A`）、招生官读后的一句话申请人形象、P0/P1/P2问题、结构诊断、逐段修改表、代表性语言问题、课程堆砌检查、`Do Not Change`、给主 Agent 的修改交接单和最终门禁判断。`portfolio-differentiation` 报告必须单独写出第八维评分、逐篇结构签名、结构风险对照和组合门禁判断。其他文书类型保留读者盲审和目标适配结构。禁止只写“更深入”“更具体”“增强个性化”等不可执行意见。

在“八维评分”之后必须追加课程堆砌检查；即使最终判断为 `Pass` 也不得省略：

```md
## 课程堆砌检查

- 具名课程数量：3
- 是否连续罗列：否
- 是否逐项连接经历与具体学习需求：是
- 课程内容占 Why Program 的比例：适中
- 判断：Pass
- 关联问题 ID：—
```

如果出现 4 门及以上具名课程、连续课程名列表、课程内容占据 Why Program 主要篇幅，或课程未连接具体经历与具体学习需求，按 `个人陈述五维质量标准.md` 生成 `PS-FIT` 问题。该项未修复时报告状态不得为 `Pass`。

## 审稿人与主 Agent 交接协议

Personal Statement 的每个问题都必须使用稳定 ID：

- 英文语言质量：`PS-LANG-001`
- 结构与逻辑主线：`PS-STRUCT-001`
- 经历与专业匹配：`PS-EVID-001`
- 个人辨识度：`PS-VOICE-001`
- 动机说服力：`PS-MOTIVE-001`
- 学校与项目匹配：`PS-FIT-001`
- 职业规划：`PS-CAREER-001`
- 跨申请组合差异：`PS-PORTFOLIO-001`
- 跨申请结构独立性与相似度：`PS-PORTFOLIO-008`

`portfolio-differentiation` 模式先执行强制的“矩阵四层约束审计”，再进行相似度和复用经历检查。审计必须逐篇生成下表，且每层均给出矩阵设计、正文证据和 `Pass/Revise`：

| 目标项目 | 事实与经历职责 | 核心问题 | 叙事动作与段落结构 | 思维人格与结尾姿态 | 总结 |
|---|---|---|---|---|---|
| Program A | 设计/正文证据/判断 | 设计/正文证据/判断 | 设计/正文证据/判断 | 设计/正文证据/判断 | Pass/Revise |

四层定义如下：

1. **事实与经历职责**：复用经历是否只承担矩阵指定的功能，而非以完整事实包、行动链和反思结论重复出现。
2. **核心问题**：删去项目名称与课程后，是否仍能辨认出本篇独有的问题，而不是泛化的可靠性、验证或边界意识。
3. **叙事动作与段落结构**：开头动作、转折动作、段落功能、能力缺口位置和结尾动作是否与矩阵一致，且不与近邻稿构成同一槽位骨架。
4. **思维人格与结尾姿态**：文章呈现的判断方式、选择/取舍与最终承诺是否具有项目特异性；若多篇都以同一抽象技术反思、同一能力缺口和同一课程/职业收束完成，则为不通过。

任一层标记 `Revise` 时，组合审稿状态必须为 `Revise`；不得以不同技术名词、不同学校资源、低词面相似度或单篇七维达标覆盖。只有四层全部 `Pass` 后，才继续执行下列组合检查：

- `PS-PORTFOLIO-001`：开头与其他目标 PS 高度相同。
- `PS-PORTFOLIO-007`：开头在同一非中性模板下重复相同信息入口和叙事动作，例如换词复述“我的兴趣始于一个问题/异常”；须给出实际同构证据，即使词面 Jaccard 较低也应判为 `Revise`。仅类别标签相同不能自动判错。
- `PS-PORTFOLIO-002`：核心经历组合、顺序和段落功能相同。
- `PS-PORTFOLIO-003`：只有职业目标或 Why Program 不同。
- `PS-PORTFOLIO-004`：同一项目导出相同能力结论，仅替换专业关键词。
- `PS-PORTFOLIO-005`：目标专业没有改变全文叙事逻辑。
- `PS-PORTFOLIO-006`：同一经历在不同 PS 中复用相同事实组合、行动链或反思结论，缺少新的语义增量。
- `PS-PORTFOLIO-008`：全文结构相似度过高，包括相同或同构的开头原型、段落功能签名、经历行动链、能力缺口位置、职业目标推导、Why Program 收束或结尾姿态；仅替换专业名、课程名或少量同义词不构成结构差异化。

第八维必须执行全文结构相似检测，至少检查：

1. 开头原型与模板族：异常/问题/兴趣来源/实习场景等非中性入口是否重复。
2. 段落功能签名：段落数量、段落职责、证据顺序、GPA/学术背景、职业规划和 Why Program 的位置是否同构。
3. 叙事动作链：同一经历是否再次完整复述“任务—方法—结果—反思”，或仅把同一行动链接到另一专业。
4. 结尾结构：是否反复使用相同的“能力缺口→项目资源→职业应用”句法和相同承诺姿态。
5. 全文成组风险：不能只比较首段或 Jaccard；必须输出逐篇结构签名、近邻高风险对和需要改变的结构变量。

第八维的结构评分建议：`9.0–10.0` 表示每个近邻目标至少改变两项因果入口、素材取舍、经历职责、能力缺口位置、职业目标生成路径或结尾姿态，且无完整非事实句/行动链复用；`8.5–8.9` 表示仅共享必要硬事实，结构与结尾独立；`8.0–8.4` 表示存在一个同构结构族或模板化收束，应 `Revise`；`7.9` 及以下表示存在多个高风险同构对、完整行动链复用或只换专业标签，应列为 `P1 / Should Fix`，必要时列 `P0 / Must Fix`。

相似度工具超过阈值只触发人工判断。若共享内容主要是 GPA、院校、项目名称等不可避免的硬事实，且叙事功能确实不同，可以 `Pass`；不得为降低数值而机械换词。

组合审稿报告必须在问题列表前加入“逐篇结构签名”表，至少包含：

```md
| 目标项目 | 段落数 | 段落功能签名 | 核心证据职责 | 与近邻项目的实质差异 |
|---|---:|---|---|---|
| Program A | 5 | 现实问题→单案例决策→认识变化→能力缺口→项目资源 | 项目X负责暴露边界 | 职业问题前置，未使用项目Y |
```

没有逐篇结构签名证据时，不得对 `portfolio-differentiation` 给出 `Pass`。出现以下情况时至少生成 `PS-PORTFOLIO-002` 或 `PS-PORTFOLIO-005`：

- 多篇文章共享同一段落数和同一段落功能序列，只在槽位内部替换经历或专业标签。
- GPA/学术背景、职业规划和 Why Program 长期出现在固定位置。
- 同一经历在多个目标中反复导出相同能力结论。
- 叙事矩阵只改变“主经历/辅助经历”的名称或顺序，没有改变全文因果路径。

不得把“开头句子不同”或“矩阵中的核心问题名称不同”单独作为组合差异化通过依据。相邻项目至少应改变两项：因果入口、素材取舍、经历职责、能力缺口位置、职业目标生成路径或结尾论证方式。组合审稿还必须列出每篇的开头原型和开头模板族；若近邻目标在同一非中性模板下重复实际叙事动作，不能以不同专业名词、不同经历名或低词面相似度覆盖。

报告还必须加入“复用经历审计”表：

```md
| 经历 | 涉及项目 | 重复的事实核 | 各篇选取片段/行动焦点/约束 | 各篇能力结论 | 判断 |
|---|---|---|---|---|---|
| Project X | A / B | 项目名、时间、真实数据 | A 聚焦决策；B 聚焦执行边界 | A 与 B 不同 | Pass |
```

如果同一经历的差别主要来自专业术语、课程连接、段落长度或同义改写，而选取片段、行动焦点、约束和能力结论仍相同，生成 `PS-PORTFOLIO-006`。必要事实重复本身不判错，但重复完整事实包和相同行动链应要求压缩、舍弃或重新选择真实片段。

同一报告内按出现顺序递增末尾数字，不得重复。`single-draft` 先输出八维评分：

```md
## 八维评分

| 维度 | 得分 | 关联问题 ID | 核心判断 |
|---|---:|---|---|
| 逻辑结构 | 8.2 | PS-STRUCT-001 | 第三段打断主线 |
| 经历与专业匹配 | 8.7 | — | 核心经历自然指向目标专业 |
| 语言表达 | 8.8 | — | 英文准确自然 |
| 个人辨识度 | 8.4 | PS-VOICE-001 | 个人判断仍不够集中 |
| 动机说服力 | 8.6 | — | 能力缺口由经历产生 |
| 学校与项目匹配 | 8.1 | PS-FIT-001 | 资源与缺口连接不足 |
| 职业规划 | 8.5 | — | 目标与前文基本一致 |
| 跨申请结构独立性与相似度 | N/A | — | single-draft 无组合输入；在 portfolio-differentiation 中必须评分 |
| **前七维平均分** | **8.5** |  | **仍因P0/P1不能Pass** |
```

随后每个问题严格使用以下字段，不得省略：

```md
### PS-FIT-001｜课程罗列削弱项目匹配逻辑

- 维度：专业与项目匹配度
- 优先级：Should Fix
- 原文定位：英文第 7 段 / 中文对应段
- 问题内容：连续列出多门课程，但没有说明各自回应的能力缺口。
- 原文证据：引用最短必要片段，或在无法安全引用时准确概述。
- 对读者的影响：读者能看出项目相关，却不知道它为何是申请人的必要下一步。
- 修改动作：保留 2–3 项资源，分别连接既有经历、能力缺口和未来用途。
- 事实边界：只使用正文已有课程和经历；不得新增项目特色或学生经历。
- 必须保留：保留申请人已经建立的核心专业动机。
- 是否需要确认：否
- 验收标准：Why Program 中每项保留资源都完成“经历—缺口—资源—用途”的连接，且不再出现课程清单。
```

最后输出给主 Agent 的唯一执行入口：

```md
## 给主 Agent 的修改交接单

| 执行顺序 | 问题 ID | 建议处置 | 可否自动修改 | 依赖信息 | 验收标准摘要 |
|---|---|---|---|---|---|
| 1 | PS-FIT-001 | 采纳 | 是 | 无 | 课程按能力缺口组织 |
| 2 | PS-VOICE-001 | 待确认 | 否 | 学生首选职业方向 | 未确认前不补写 |
```

“可否自动修改”只能填 `是` 或 `否`：`Must Fix` 和可安全处理的 `Should Fix` 可填 `是`；`Optional` 默认填 `否`；`Needs Confirmation` 必须填 `否`。

## 单篇、组合与补充复核的独立计数

PS 初始 `single-draft` 审查使用 `C1` 至 `C5`。`C1` 是初次内容审稿；平均分低于 8.5 或存在 P0/P1 时，主控 Agent 生成净化修改交接包并调用隔离修改 worker，得到下一个内部 `Rn`。候选稿重新通过 `application-review` 后，启动全新、无上下文继承的审稿 Subagent 执行下一轮 `Cn`。`C5` 仍未通过则停止、不发布；`C5` 通过则与较早通过完全一样，进入必需的组合审稿，不因单篇次数已满而停止。

同一学生已有其他申请目标时，组合 `portfolio-differentiation` 必须由不同的全新隔离 Subagent 执行，独立使用 `P1` 至 `P5`，不占用 `C` 轮次。第 `Pn` 轮为 `Revise` 且 `n<5` 时，主控 Agent 先制作净化问题单，另起全新隔离修改者生成下一个内部 `Rn`；该稿通过 `application-review` 后，由全新隔离审稿人按 `single-draft` 执行补充单篇复核 `S1` 至 `S5`。`S` 轮只用于组合触发修改后的当前稿，不占用 `C` 或 `P`。补充单篇复核若为 `Revise`，继续在剩余 `S` 轮次内净化交接、隔离修改、事实审查和全新单篇复核；只有 `S` 为 `Pass`，才能由另一个全新隔离审稿人执行下一轮 `P(n+1)`。`S5` 或 `P5` 仍未通过则停止、不发布。

- 每份报告在 frontmatter 分别记录实际使用的 `C`、`S` 或 `P` 轮次；不得把三套计数合并、互相抵扣或重置，正式 `Vn` 始终不变。
- 任何轮次出现 `Blocked` 都立即停止，不消耗猜测式修改轮次。分数上升不能作为唯一完成依据；每轮必须核销问题 ID，并通过事实审查。
- 多目标 PS 的最终候选必须同时具有当前稿的事实 `Pass`、单篇 `Pass`（初始 `C` 或修改后的补充 `S`）和组合 `P` 的 `Pass`；仅有前两项不得正式发布。

## 返回主控 Agent

主控 Agent 必须先制作“建议—采纳决策表”，再调用 `application-revision`：

- 自动处理 `Must Fix` 和被采纳的 `Should Fix`。
- `Optional` 默认不触发新版本。
- `Needs Confirmation` 只进入待确认项，未经用户确认不得写入正文。
- 修改由全新、上下文隔离的修改 Subagent 按 `application-revision` 执行；审稿人不得亲自修改。
- 修改后生成下一个内部 `Rn` 候选稿，预留的正式 `Vn` 不变，再调用 `application-review` 做事实与合规兜底。
- 事实审查通过后按修改来源启动新的隔离单篇审稿人：初始单篇修改进入下一 `Cn`，组合修改进入下一 `Sn`；补充单篇通过后另起全新隔离组合审稿人进入下一 `Pn`。不得把上一轮完整报告传给新审稿人。
- 修改时按交接单顺序处理，并以每条问题的“验收标准”逐项复核；不得只根据问题标题自由发挥。

## 常见错误

- 让原写作者直接执行本 skill：不具备独立性，应启动隔离 Subagent。
- 已隔离的最终审稿人再次派生 Subagent：造成递归和职责漂移；看到“已隔离的最终审稿人”标记后必须直接审稿。
- 把所有建议都列为必须修改：会造成无止境修稿和风格磨平。
- 用常识补全领导力、动机或职业细节：应标记 `Needs Confirmation`。
- 直接改稿：审稿人只报告，主控 Agent 决定是否采纳。
- 读取完整资料库：会污染盲审；事实兜底仍由 `application-review` 完成。
- 在 `single-draft` 模式读取旧稿：会破坏单篇盲审。
- 在 `portfolio-differentiation` 模式不提供其他目标 PS：无法判断跨申请重复。
- 为降低相似度机械替换同义词：没有改变叙事，应继续判为 `Revise`。
