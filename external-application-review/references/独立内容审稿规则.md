# 独立内容审稿规则

## 通用问题

- 读完后能否用一句话概括申请人的主线与核心优势？
- 开头是否尽快进入申请人的具体问题、判断或经历？
- 每段是否承担不同功能，段落顺序是否形成因果推进？
- 经历是否包含选择、行动、反思或能力迁移，而非项目报告式罗列？
- 职业目标、学习需求与目标项目是否相互连接？
- 是否有重复结论、方法清单、课程清单或空泛评价？
- 哪些内容最具辨识度，修改时必须保留？

## 文书类型

### Personal Statement

必须读取 `个人陈述五维质量标准.md` 并逐维审查。检查兴趣来源、经历证据、能力增长、职业目标和项目匹配是否形成一条主线。Why Program 应解释能力缺口与项目资源的对应关系，不以课程罗列代替论证。跨专业申请必须解释转向逻辑。

### Recommendation Letter

检查推荐人的观察视角是否可信、例证是否支持评价、评价是否有层次、推荐力度是否自然。不得要求加入推荐人不可能观察到的学生内心活动或新事实。

### Resume

检查信息层级、相关性、经历排序、bullet 的动作与结果、重复和阅读效率。没有事实依据时不得建议添加数字。

### Resume-Experience

检查每个项目的功能是否清楚、bullet 是否互补、技术细节是否服务岗位或专业方向，以及是否过度泛化。

## 建议质量门槛

每条建议必须同时满足：

1. 能定位到具体段落、句子或结构位置。
2. 能解释对读者理解或说服力的实际影响。
3. 能给出删除、压缩、移动、合并、重写或待确认等明确动作。
4. 能说明是否可由现有文本完成。

缺少其中任何一项，降级为 `Optional` 或删除该建议。

## 防止过度修改

- 不为追求戏剧性强迫增加故事化开头。
- 不把自然、朴素的表达统一改成华丽语言。
- 不因还能微调就判定 `Revise`。
- 不用审稿人的职业偏好替代申请人的真实目标。
- 至少列出两项 `Do Not Change`；若不足两项，应说明原因。
