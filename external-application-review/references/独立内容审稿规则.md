# 独立内容审稿规则

## 通用问题

- 读完后能否用一句话概括申请人的主线与核心优势？
- 开头是否尽快进入申请人的具体问题、判断或经历？
- 每段是否承担不同功能，段落顺序是否形成因果推进？
- 经历是否包含选择、行动、反思或能力迁移，而非项目报告式罗列？
- 职业目标、学习需求与目标项目是否相互连接？
- 是否有重复结论、方法清单、课程清单或空泛评价？
- 哪些内容最具辨识度，修改时必须保留？

## 文书类型

### Personal Statement

必须读取 `个人陈述五维质量标准.md` 作为质量边界，并读取 `个人陈述八维评分与校准标准.md` 完成量化审稿。前七维用于单篇评分；同一学生有多个目标时，第八维专门检查跨申请全文结构独立性。按“内容论证→结构→段落功能→语言表达”的顺序检查兴趣来源、经历证据、能力增长、职业目标和项目匹配是否形成一条主线。Why Program 应解释具体学习需求（深化、迁移、整合或补足能力）与项目资源的对应关系，不以课程罗列代替论证。跨专业申请必须解释转向逻辑。

当 `review_scope` 为 `portfolio-differentiation` 时，横向比较同一学生不同目标 PS。重点判断目标专业是否真正改变核心问题、开头、素材排序、经历功能和能力结论。共享院校、GPA、项目名称等硬事实不自动构成问题；复用完整非事实句、相同前三段叙事、相同项目顺序，或只替换最后的职业目标和项目课程，应生成 `PS-PORTFOLIO` 问题。

组合审稿必须先逐篇抽取段落功能签名和结构签名，例如“问题钩子→学术背景→主案例→辅助案例→职业目标→项目匹配”。签名比较的是每段在论证中的职责、开头原型、能力缺口位置和结尾姿态，不是关键词。若多篇稿件只是把不同经历装入相同槽位，或者所有稿件都固定使用 GPA 第二段、职业规划倒数第二段和 Why Program 末段，即使文字相似度很低，仍属于结构同构，并必须计入第八维。

审稿时进一步检查：

- 每篇是否有唯一核心命题，而不是同一成长故事连接不同专业标签。
- 是否存在主动舍弃素材，还是每篇都自动使用“主经历 + 辅助经历”。
- 相邻项目是否至少改变两项：因果入口、素材取舍、经历职责、能力缺口位置、职业目标生成路径或结尾方式。
- 同一经历能否在去掉专业名称后仍导出清楚不同的能力结论。
- 删除末段后，正文是否仍自然指向目标领域。

报告必须展示逐篇结构签名表；缺少该表不得判定组合审稿 `Pass`。

第八维必须有全文证据，而不是只报告首段相似度。审稿人应至少输出：开头模板族、段落功能序列、核心证据职责、能力缺口位置、职业目标生成路径、Why Program 功能、结尾姿态、近邻高风险对和建议改变的结构变量。完整行动链或相同结尾姿态的复用，不能通过更换专业名、课程名或同义词消除。

还必须逐项审计跨稿复用经历。比较的不只是经历名称，而是每篇实际使用的事实组合、行动链、约束和反思结论。若同一经历在不同文章中都完整复述相近的项目背景、方法、数据、结果和能力结论，即使开头、段数和 Why Program 不同，仍应生成 `PS-PORTFOLIO-006`。

审计时区分：

- 可接受：必要硬事实的最小复用，但选取片段、问题、行动焦点、约束和能力结论有真实差异。
- 需要修改：相同事实包和行动链只换专业术语，或同一反思被连接到不同课程。
- 推荐动作：删除弱复用经历、压缩成一句背景，或从资料中改选另一个真实片段。
- 禁止动作：为了制造差异补写资料中不存在的新冲突、新行动或新结果。

### Recommendation Letter

检查推荐人的观察视角是否可信、例证是否支持评价、评价是否有层次、推荐力度是否自然。不得要求加入推荐人不可能观察到的学生内心活动或新事实。

### Resume

检查信息层级、相关性、经历排序、bullet 的动作与结果、重复和阅读效率。没有事实依据时不得建议添加数字。

### Resume-Experience

检查每个项目的功能是否清楚、bullet 是否互补、技术细节是否服务岗位或专业方向，以及是否过度泛化。

## 建议质量门槛

每条建议必须同时满足：

1. 能定位到具体段落、句子或结构位置。
2. 能解释对读者理解或说服力的实际影响。
3. 能给出删除、压缩、移动、合并、重写或待确认等明确动作。
4. 能说明是否可由现有文本完成。

缺少其中任何一项，降级为 `Optional` 或删除该建议。

## 防止过度修改

- 不为追求戏剧性强迫增加故事化开头。
- 不把自然、朴素的表达统一改成华丽语言。
- 不因还能微调就判定 `Revise`。
- 不用审稿人的职业偏好替代申请人的真实目标。
- 至少列出两项 `Do Not Change`；若不足两项，应说明原因。
