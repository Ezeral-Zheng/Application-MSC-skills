# Application Revision

## 使用场景

当用户要求“根据反馈修改”“润色”“重写某版”“学生说不喜欢某种表达”“按老师意见改”等时使用。

本 skill 有两种互斥模式：

- `direct-feedback`：用户或学生直接提出修改要求，由主控 Agent 在当前任务上下文中执行默认流程。
- `isolated-review-fix`：修改源自 `external-application-review`，必须由全新隔离修改 Subagent 执行，并以“隔离修改协议”覆盖默认读取规则。

隔离修改者收到“你是已隔离的修改执行者”标记时，必须直接进入 `isolated-review-fix`。该模式完全跳过下方“默认流程”、版本扫描、正式发布、历史写入、偏好更新和审查调用，只执行“隔离修改协议”，只使用净化交接包列出的输入。

## 默认流程（仅 direct-feedback）

1. 识别学生、文书类型和目标稿件。
2. 读取原稿、学生反馈、相关资料源和 `Student_Profile/学生偏好总结.md`。
3. 先判断学生反馈是“核心诉求/修改方向”还是“明确要求逐字替换”。
4. 按文书类型套用修改规则。
5. 扫描正式历史文件并预留下一个交付版本 `Vn`；先把修改稿保存为临时 `R1` 候选稿，不写入正式输出目录。
6. 调用 `application-review` 审查候选稿；对于简历，只有事实与格式 `Pass` 后才进入 `resume-quality-review`。
7. 如果审查为 `Needs Fix`，根据审查报告自动生成下一个内部 `Rn` 并复查，最多新增 3 个内部轮次；正式 `Vn` 保持不变。
8. 如果审查为 `Blocked`，停止自动修稿并报告需要补充的信息。
9. `application-review` 为 `Pass` 后，Personal Statement 无论修改来源是什么，都必须进入 `external-application-review` 的内容门禁：初始单篇 `C1-C5` 负责前七维，多目标 PS 的独立组合 `P1-P5` 负责第八维；组合修改后的补充单篇复核 `S1-S5` 不占用 `C` 或 `P`。即使 `C5` 才通过，仍必须进行组合审稿；其他文书按总控规定执行对应独立内容审稿。
10. 独立内容审稿为 `Revise` 时，主控 Agent 先制作建议采纳决策表，只处理 `Must Fix` 和被采纳的 `Should Fix`，再制作净化修改交接包并启动全新隔离修改 Subagent；`Needs Confirmation` 不得自动写入正文。
11. 隔离修改者按交接包中的问题 ID 和执行顺序处理，用验收标准复核，只把下一个内部 `Rn` 和问题核销表写入任务专用临时目录。
12. 主控 Agent 对新 `Rn` 调用 `application-review`；事实门禁通过后按来源启动新的隔离单篇审稿人：初始单篇修改进入下一 `Cn`，组合修改进入下一 `Sn`，补充单篇 Pass 后另起全新隔离组合审稿人进入下一 `Pn`。三套计数各有五轮上限，不得因本次最初是用户反馈修改而跳过或重置。
13. 简历的质量审查若返回 `Revise`，根据净化问题单修改后必须重新经过 `application-review` 和 `resume-quality-review`；质量轮次最多 Q1-Q5，平均分必须达到 8.5 且无 P0/P1。全部门禁通过后，把最后候选稿一次性保存为预留的正式 `Vn`，并只向用户展示该正式版本。
14. 正式发布后才生成 `Revision_History/文书类型-目标-Vn-修改总结.md`、更新 `Student_Profile/学生偏好总结.md`，并按规则写入最终 `Review_History/`、`External_Review_History/` 和 `Review_Memory/`。内部阶段不得提前写入。

## 隔离修改协议

当修改来自独立内容审稿时，修改必须由全新 Subagent 执行。修改 Subagent 不继承任何现有上下文，也不能与任一轮审稿 Subagent 复用同一任务或会话。调用提示必须明确写明“你是已隔离的修改执行者”，收到该标记后直接执行修改，不得继续派生审稿人或其他修改者。

隔离修改 Subagent 不负责版本号、正式文件、审查调用、历史记录、偏好记忆或最终发布。这些职责全部留在主控 Agent。隔离修改者的完整输出仅为任务临时目录中的下一个 `Rn` 和问题核销表。

主控 Agent 只能向修改者传入经过净化的最小输入包：

1. 当前唯一的 `Rn` 候选稿；不得同时提供旧候选稿或正式历史稿。
2. 已采纳问题的结构化交接单：问题 ID、优先级、原文定位、问题影响、修改动作、事实边界、必须保留内容和验收标准。
3. 最小事实包：本次修改允许使用的已确认事实、对应来源路径和必要原文摘录；不得只给结论而不给来源。
4. 本次输出要求：文书类型、目标项目、语言、字数、双语和段落格式等。
5. 下一个内部候选稿和问题核销表在任务专用临时目录中的明确输出路径。
6. PS 修改所需的通用语言参考路径：`../personal-statement-writer/references/申请文书高级句式与信息组织指南.md` 与 `../personal-statement-writer/references/全文句式与信息组织重构.md`、`../personal-statement-writer/references/PS时间表达与学业阶段.md`（相对本 skill 目录）。主控须在净化包中明确列出；这是通用方法资料，不得包含写作过程或上一轮评价。

不得向修改 Subagent 传入：

- 完整独立审稿报告、八维评分表、平均分或上一轮得分。
- 写作过程、作者解释、主 Agent 的推理、预期分数或审稿人身份。
- 旧候选稿、上一轮修改过程、上一轮问题核销表或历史修改总结。
- `Review_History/`、`Revision_History/`、`Review_Memory/` 的完整内容。
- 其他学生文件，或当前任务不需要的同一学生历史材料。

主控 Agent 必须把完整审稿报告先转换为净化交接包。修改者只解决被采纳问题，不为追逐分数进行无目标润色，也不接触未采纳的 `Optional` 或未经确认的 `Needs Confirmation`。如果平台无法创建全新隔离修改 Subagent，状态为 `Blocked`，不得由审稿人或原写作者直接代替。

隔离修改者完成后输出两项：

1. 新的内部 `Rn` 候选稿。
2. 问题核销表，逐项标记 `Resolved`、`Partially Resolved` 或 `Blocked`，并指出修改位置。

问题核销表只是主控 Agent 的过程材料，不能传给下一轮独立审稿人。下一轮审稿人只读取新的候选稿与新的净化审稿输入包，从零重新评分，避免被上一轮问题和分数锚定。

## 过程材料边界

- 审稿报告、建议采纳决策表、净化修改交接包、最小事实包、内部 `Rn` 候选稿和问题核销表都只保存在通过 `mktemp -d` 创建的任务专用临时目录。
- 上述过程材料不得进入学生正式输出目录、`Review_History/`、`External_Review_History/`、`Revision_History/`、`Review_Memory/` 或版本索引。
- 正式发布后只保留最终 `Vn`、最终事实审查报告、最终独立内容审稿报告和面向用户的修改总结。
- 初始单篇到 `C5`、组合修改后的补充单篇到 `S5` 或组合审稿到 `P5` 仍未达到各自门槛时，不发布预留的正式 `Vn`；只按总控规则生成不包含内部候选全文的 Failure Report。`C5` 已 Pass 不能作为跳过 `P1` 的理由。

## 参考资料

- 本 skill 的参考文档放在 `Application_System/skills/application-revision/references/`。
- 可放修改标准、常见反馈处理方式、润色前后对照、学校审稿要求、禁用表达清单等。
- 修改前如参考目录中有与当前文书类型、反馈类型、学校或目标风格相关的文件，应优先读取相关文件；不要无差别读取全部参考资料。
- PS 修改前完整读取 [申请文书高级句式与信息组织指南.md](../personal-statement-writer/references/申请文书高级句式与信息组织指南.md)。`isolated-review-fix` 由主控将该路径列入允许输入；只读此通用参考，不读取写作 skill 或学生历史。指南的教学事实不得进入正文。另须读取 [全文句式与信息组织重构.md](../personal-statement-writer/references/全文句式与信息组织重构.md)，并由主控一并列入隔离修改允许清单。

## 版本规则

- 修改稿不覆盖原稿；内部候选稿也不得进入正式输出目录。
- 修改前扫描目标输出目录中过往同类文件的最高版本。
- 如果最高正式交付版本是 `V3`，本次任务最终保存为 `V4`；即使内部经历 `R1`、`R2`、`R3`，仍只发布 `V4`。
- 可用 `Application_System/tools/next_version_path.py` 生成新版 `.md` 路径。

## 学生反馈处理规则

- 学生反馈中可能包含“希望改成什么样”的示例句、示例段落或参考表达；默认不要直接照搬。
- 默认做法是先提炼示例背后的核心诉求、修改方向和不满意点，再结合原稿、资料事实、文书类型规则和自身判断重新改写。
- 只有当用户明确要求“一模一样改成”“逐字替换”“直接用这句话”“不要改动这段表达”等强指令时，才按原文照搬或逐字替换。
- 如果学生给出的示例表达有事实风险、语气不适合、逻辑不顺、与文书类型不匹配或会造成重复，应保留其意图但重写表达。
- 修改总结中应记录：本次是否有学生示例改法、是否逐字采用、没有逐字采用的原因。

## 修改稿格式规则

- 所有修改后的正文段落之间不要空行；段落应连续排列。
- 所有修改后的正文段落开头不要空格、不要缩进、不要使用中文全角空格。
- 保留 Markdown 标题、列表、表格等结构本身需要的换行；本规则主要约束推荐信、PS 等连续正文段落。
- 如果原稿有段首缩进或段落间空行，修改时应统一清理。

## 类型规则

推荐信：

- 保持推荐人第三方口吻。
- 优先修改真实性、具体交集、推荐人身份一致性。
- 不把推荐信改成学生自述。

个人陈述：

- 读取 `Application_System/skills/external-application-review/references/个人陈述五维质量标准.md`。
- 独立内容审稿产生的 PS 修改必须读取净化交接包，不得直接读取八维评分或完整审稿报告。
- `direct-feedback` 模式读取 `Student_Profile/PS_申请组合叙事矩阵.md` 和同一学生其他申请目标的最新正式 PS。
- `isolated-review-fix` 模式禁止直接读取叙事矩阵和其他正式 PS；若某项组合差异修改必须使用这些信息，由主控 Agent 抽取完成该项修改所需的最小差异事实并写入净化交接包。
- 保持第一人称主线清晰。
- 默认保持同一 `.md` 文件内英文在前、中文在后的双语连贯文章，不分点，不改成提纲或清单。
- 修改英文版和中文版时必须保持事实一致；中文可自然改写，但不得新增英文版没有的事实。
- 英文正文默认必须为 700-1000 words，目标约 800 words；如果项目官方有明确字数要求，以任务输入中的项目级范围为准。修改时优先压缩空泛表达，但不得把正文压到适用下限以下；不足时应优先补足已确认事实的论证、行动焦点、能力边界和项目匹配，不得编造新事实。
- 应届生 PS 覆盖本科专业选择原因、本科经历、职业规划、硕士专业/学校选择原因四项信息责任，依据本篇论证关系组织；不强制固定信息顺序、段落数量或模板。
- 优先修改申请动机、专业匹配、项目/课程证据、职业目标。
- 收到 `PS-FIT` 课程堆砌问题时，默认压缩到 2–3 门最相关课程或资源，并逐项建立“经历—具体学习需求—课程价值—未来应用”；不得仅把课程列表改写成长句。
- 收到 `PS-PORTFOLIO` 或 `Cross-Application Similarity` 问题时，先重新确定本篇核心命题、因果路径、证据职责、主动舍弃素材和目标结构签名，再重写相关段落；不得用同义词替换、交换经历顺序、轮换主辅经历或只改最后两段来完成。
- 修订后的相邻项目至少改变因果入口、素材取舍、经历职责、能力缺口位置、职业目标生成路径或结尾方式中的两项；不得保留统一的 GPA 第二段、职业规划倒数第二段和 Why Program 末段。
- `direct-feedback` 模式收到 `PS-PORTFOLIO-006` 或经历段复用问题时，由主控 Agent 读取该经历在其他最新正式 PS 中的全部段落，区分不可变事实核和可舍弃内容；`isolated-review-fix` 修改者不得自行读取，只能使用主控写入净化交接包的最小差异事实。
- 修订同一经历时，至少实质改变上述五项中的三项；无法做到时删除该经历或压缩为一句背景。不得只调整字数、句序、同义词或专业标签。
- 修改段落资源分配时，不平均扩写或压缩每项经历；由核心案例和论证职责决定篇幅。弱辅助经历优先删除。
- 相同硬事实可以保留；相同项目复用时须有实质不同的论证功能和能力结论。学习需求可来自深化成果、迁移方法、整合能力、职业延伸或补足能力，不要求每项经历都以局限收尾。
- 减少空泛评价，增加可证实细节。
- 修改后复核事实来源和时间线，删除或标记无法核实的信息。

### PS 时间表达修改

- 完整读取 [PS时间表达与学业阶段.md](../personal-statement-writer/references/PS时间表达与学业阶段.md)，隔离模式由主控加入允许清单。直接反馈修改及被采纳的全文规则修订须清理无必要个人年月和预计毕业信息；仅局部授权时核对所改内容，发现范围外问题返回主控，不擅自扩大修改。
- 年级表达只能由最小事实包中的实际入学、学制、校历和进度证据支持，不凭当前年级、公历相减或预计毕业时间倒推。明确区分暑期在某年级结束后/下一年级开始前，跨年经历不能整体并入一个年级；证据不足则省略年级，保留经历事实。
- 未来计划不得改成完成，日期省略不得改变先后、重叠、时长和因果；保留有必要的正式名称/数据年份或题目要求。核销表附本轮原始时间—依据—阶段—正文表达/省略映射，留在临时目录，不传入下一轮内容盲审。中文如适用同步核对。

### PS 语言与信息组织修改

- 类型规则和结构签名里的“能力缺口”按具体学习需求理解，可为深化、迁移、整合或补足能力；保留有作用的真实边界，不把每段改成发现不足。
- 用户要求全文润色、句式丰富或信息组织优化，或净化包采纳全文语言问题时，必须执行“全文诊断 → 段落信息层级重构 → 跨段节奏复核 → 全文语义与词数核验”；按通用全文参考检查每段，不只处理几个开头。即使各句信息不同，持续相同的主句骨架仍可能需重构。跨稿比较遵守两种模式的读取边界。
- `These experiences/findings/insights`、led/prompted/motivated、What/Having/Although 或 which/thereby 的重复只是复核信号。先识别重复的判断或动机宣告，必要时合并、删减、改选证据；不能仅换同义词，也不对句式设次数上限。
- 主动用主从安排、非谓语、同位语、对照、具体对象承接及合并/拆句组织已有信息，让主要判断、背景和条件形成层级。仅给 I 加状语或把 I hope 换成 I aspire 不算全文重构；未来愿望不得升级为确定承诺。保留有功能的短句与个人行动，不强行补出顿悟、失败、能力缺口或新的“高级”开头。
- 用最小事实包核对执行者、个人/团队职责、时间顺序、完成状态、范围、情态、因果与认知强度；核对分词主语、从句指向和标点。缺乏依据的具体洞察不得补造。
- 修改后通读完整文章，保护有效成果、个人声音与未涉问题的内容。`isolated-review-fix` 只修采纳项及必要衔接；采纳项是全文句式问题时，全文即授权范围，不得借“只做局部修改”缩减任务。仅采纳局部问题时不扩展无关润色。全文问题的核销表须覆盖各段的信息层级、节奏及重构/保留理由，不能只列几个改词。更新中文对照并复核全文词数；仍按既有门禁执行，不增加审查轮次。

简历：

- 优先修改结构、bullet 动词、结果表达、经历排序。
- 保持简洁，不写成长段 PS。
- 不虚构数字或成果。

## 修改总结

每次修改总结至少包含：

- 原稿路径
- 新稿路径和版本号
- 反馈来源或反馈内容摘要
- 本次主要改动
- 仍需人工确认的问题
- 可沉淀为学生偏好的观察
- 审查状态和最终通过版本
- 如来自独立内容审稿：审稿报告路径、建议采纳/拒绝/待确认情况
- 不在正式修改总结中暴露内部 `Rn`、`Cn`、八维逐轮得分或过程文件路径

## 阻塞条件

- 找不到原稿或无法确认要修改的版本。
- 学生反馈与事实资料冲突，且无法判断应以哪一方为准。
- 反馈要求会导致伪造经历、成绩、项目、时间、奖项或学校信息。
- 关键资料缺失，继续修改会导致编造。
- 无法创建不继承现有上下文的全新隔离修改 Subagent。
