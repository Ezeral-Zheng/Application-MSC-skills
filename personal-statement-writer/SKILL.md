# Personal Statement Writer

## 使用场景

当用户要求为某个学生写 PS、SOP、个人陈述、申请动机文书时使用。

用户仅要求生成或增补叙事矩阵时，改用 `ps-narrative-matrix`，不提前写 PS。用户要求先给学生看方案再写正文时，先按该 skill 交付学生版；其六列总览与十一字段卡片不包含本 skill 的内部审计记录。后续正文写作读取最新学生版的已确认方案，并在工作矩阵中补充写作所需约束。

## 必读资料

1. `Student_Profile/学生偏好总结.md`
2. `Student_Profile/PS_申请组合叙事矩阵.md`
3. `Personal_Statement/` 中同一学生其他申请目标的最新正式 `Vn`；同一申请目标只读取最高版本
4. `Basic_Info/*.md`
5. `Personalization_Info/*.md`
6. `Personalization_Materials/*.md`
7. `Course_Info/*.md`
8. `Resume/*.md`
9. `Major Selected/*.xlsx` 或同目录下后续补充的专业库文件；如果暂时无法解析 Excel，以用户本次明确指定的学校、专业和方向为准，不因无法提取 Excel 阻塞写作
10. 如果常规资料中出现附件文件名，读取 `Additional_Documents/` 中匹配的同名 `.md`
11. 用户提供的申请专业、项目、学校或方向信息
12. `Application_System/skills/external-application-review/references/个人陈述五维质量标准.md`，作为写作阶段的质量目标，而不是等审稿时才补救

如果 `Personalization_Materials/` 为空、缺失或只有模板内容，先使用 `personalization-material-importer` 生成“个性化素材补写候选”。补写候选只能基于已读取资料和申请方向做主题提炼、动机延展、能力迁移和待确认问题整理；不得把未经确认的具体经历、时间、奖项、成绩、课程或公司写成事实。

## 未明确的转向动机与职业方向

学生资料未直接说明申请某一方向的转向动机、短期岗位或长期职业方向时，写作者应在已有事实、学生已表达的偏好、目标项目的实际培养内容和合理职业路径之间建立因果链，自行形成具体、可信且有阶段性的申请叙事；**不因缺少学生对这两类未来意向的原话而要求确认、留占位符或阻塞交付**。用户已授权代写时，无须再就写作者构建的动机和职业规划单独征求学生同意。

- 转向动机连接已有经历中的成果、可迁移能力、真实问题或职业延伸与目标领域的下一步学习价值，不虚构决定转向的事件、长期热爱、实验经历或他人影响。
- 职业方向写成“硕士阶段拟获得的能力 → 毕业初期希望承担的具体工作或问题 → 较长期希望发展的职责”；可在第一人称正文中使用 `I aim to`、`I hope to`、`I plan to` 等面向未来的表达，避免把未确认的职位、雇主、录用结果或终身承诺写成既成事实。
- 方向应与申请项目和可迁移能力相符；若要声称“学校希望候选人具备某项职业规划”，须有项目官方材料支持，不臆测招生偏好。多项目申请时，各篇规划要由本篇问题独立推导，不只是换岗位名称。
- 在内部素材判断或叙事矩阵中标记“写作者基于材料构建的申请方向”，便于追溯；正式 PS 正文不需要插入待确认标记或向学生征求批准。学生已有明确且相冲突的职业偏好、时间线或目标时，以该信息为准，不得覆盖。

此授权仅适用于对未来意向的合理写作构建，**不适用于编造过去或现在的事实**，包括做过的项目、动作、成果、成绩、课程、雇主、实习及已作出的决定。缺少支撑因果链的基本教育和经历事实、或资料之间存在无法裁定的关键事实冲突时，仍按阻塞条件处理。

## 参考资料

- 本 skill 的参考文档放在 `Application_System/skills/personal-statement-writer/references/`。
- PS 写作前完整读取 [申请文书高级句式与信息组织指南.md](references/申请文书高级句式与信息组织指南.md)，并在语言复核时按其第 6、8、9 节检查。教学例句不构成学生事实、动机或成果依据；不设复杂句配额。
- 写作及全文语言重构还须读取 [全文句式与信息组织重构.md](references/全文句式与信息组织重构.md)，把指南用于完整文章的信息层级与节奏，不停留在局部去重复。
- 可放 PS/SOP 范文、项目匹配材料、学校文书题目、风格样例、禁用表达清单等。
- 写作前如参考目录中有与当前学校、项目、专业、题目或目标风格相关的文件，应优先读取相关文件；不要无差别读取全部参考资料。

## 角色定位

写作时以“精通理工科与经济学科相关知识的学者和申请文书作者”身份工作。目标不是罗列素材，而是理解申请人的学术背景、经历和申请目标，写出事实准确、逻辑连贯、适合申请用途的双语个人陈述；英文版本作为正式申请稿优先输出，中文版本作为同文件内的对照稿紧随其后。

## 拆解流程（限定来源）

写作前先拆解用户资料，形成内部素材判断，不在最终文章中分点展示。必须覆盖以下信息维度：

- 申请信息：申请学校、申请专业、项目方向、课程组成、专业前景。
- 专业库信息：目标学生 `Major Selected/` 中与本次申请学校、专业或方向匹配的项目信息；如未能读取，则使用用户本次明确给出的专业信息。
- 学历背景：本科院校、本科专业、核心课程、专业成绩、排名或 GPA。
- 本科经历：课程项目、科研经历、实习经历、竞赛经历、团队经历、问题解决经历。
- 专业选择原因：为什么选择本科专业，为什么继续申请目标硕士专业和学校。
- 职业规划：短期目标和长期目标。
- 个性化素材：腾讯文档中明确提供的个人化表达、动机线索、经历反思、职业偏好，以及补写候选中的可安全使用方向。
- 时间节点：经历发生顺序、课程/实习/项目时间、未来规划时间跨度。

## 时间表达与学业阶段

写作前完整读取 [PS时间表达与学业阶段.md](references/PS时间表达与学业阶段.md)。默认省略无必要的具体个人年月和预计毕业信息；需要定位时才用有证据的年级或经历语境。按实际入学、学制、进度和校历核实，特别区分年级结束后的暑期与下一年级；跨学年经历不压成单一年级，不能从预计毕业时间倒推。资料不足时省略年级，不猜。内部时间映射留在任务临时目录；不改源资料，不传入内容盲审。未来计划仍是未来，双语保持同一边界，正式名称/数据年份及题目要求的必要日期不机械删除。

## 学生类型判断

成文前先判断学生主要属于哪类画像，并据此选择材料重心：

- 学术/科研导向：突出课程、科研、项目方法和研究兴趣。
- 实习/职业导向：突出实习、行业观察、职业目标和能力迁移。
- 跨专业/方向转换：重点解释转向原因、已有基础和目标专业匹配。
- 经历较少但课程扎实：强化课程、作业项目、专业理解和职业规划。
- 综合型：在课程、项目、实习与规划之间建立统一主线。

类型判断只用于内部写作，不要在最终文章中写成标签。

## 写作前的申请组合论证设计

本 skill 中矩阵与结构签名里的“能力缺口”字段按具体学习需求理解，可填写深化、迁移、整合或补足能力；若不存在有依据的不足，不得为填字段制造失败。下方架构示例只展示可能路径，不要求使用相同的缺口收尾。

写作正文前必须先做学生级横向规划，并更新 `Student_Profile/PS_申请组合叙事矩阵.md`。不得先列出 A、B、C、D 经历再调换顺序；先建立本篇唯一的核心命题，再选择能够完成论证的证据。矩阵至少记录本次目标项目的：

- 目标项目与方向。
- 一句话核心命题：全文最终要让读者相信什么。
- 当前核心问题：本篇要论证什么学习方向，以及哪些真实成果、能力、问题或职业任务支持它；不要求每篇都有尚未解决的问题。
- 证据链：哪些事实支持起点、行动、判断或成果，以及进一步学习的价值；能力边界只在有依据且有论证作用时展开。
- 因果路径：全文如何从具体问题推进到学习需求与项目选择。
- 开头切入点，以及为什么它是本篇因果起点。
- 必须使用的证据、可选证据和主动舍弃的经历。
- 重点能力和具体学习需求（可为深化、迁移、整合或补足能力）。
- 职业目标。
- Why Program 对接资源。
- 与已有 PS 允许复用的硬事实。
- 必须避开的既有开头、段落功能序列、能力结论和结尾方式。
- 写作前预期结构签名，例如“现实问题→单案例决策→认识转变→能力缺口→项目资源”，不得只记录经历名称。
- 开头原型：先从真实材料中决定读者需要先知道什么，再记录其原型并与相邻目标比较（例如现场决策、结果反推、对照冲突、职业任务、系统边界或观察转折）；不得连续使用“我的兴趣始于一个问题/异常”“My interest began with...”等兴趣来源模板。若开头实际执行相同的叙事动作、重复同一论证入口，即使词面相似度低也必须重构；原型名称只是描述，不能靠轮换标签完成差异化。
- 每项复用经历的语义增量：本篇新选择的片段、问题、行动焦点、约束和能力结论。

写作完成后、进入正式发布前，必须执行一次“矩阵四层约束自检”，并把每层的正文证据写入任务临时目录：

1. **事实与经历职责**：正文是否只使用矩阵分配的最小事实核；每项复用经历是否承担预定且不可互换的职责。
2. **核心问题**：正文是否真正围绕本篇独有的问题推进，而不是把相同“可靠、可验证、证据边界”等抽象判断换到不同专业。
3. **叙事动作与段落结构**：开头动作、转折动作、段落功能序列、能力缺口出现位置与结尾动作是否实现矩阵设计，且不与近邻稿形成同一骨架。
4. **思维人格与结尾姿态**：读者是否能从选择、取舍、判断方式和结尾承诺中辨认出本篇独有的申请人侧面；不得让所有稿件都呈现相同的“技术反思者”口吻，再以相同的“能力缺口—课程—职业”姿态收束。

任何一层无法提供正文证据或被判为不满足时，候选稿必须进入修改；不得以素材不同、词面相似度低或学校资源不同代替四层通过。

同一事实允许在多个项目中出现，但必须服务不同的申请逻辑。不得把一篇既有 PS 作为底稿，只替换专业名称、职业目标、课程和最后一段。

如果同一学生还没有其他正式 PS，建立首条矩阵记录即可。如果已有其他专业 PS，则先比较已有主线与素材分配，再决定本篇从哪个专业问题切入。

## 核心命题与证据选择

正文动笔前，在内部完成以下判断：

1. 用一句话写出核心命题，连接已有事实与能力、具体学习需求和目标项目的价值。深造需求可来自成果深化、方法迁移、新场景应用、能力整合、职业延伸或尚未解决的问题；不要求把每篇都写成发现不足后求学。
2. 为核心命题选择最少且足够的证据。没有独立论证功能的经历必须删除，不因素材优秀而强行纳入。
3. 为每项保留经历指定不可互换的职责，例如触发问题、提供反例、展示决策、暴露能力边界或验证职业方向。
4. 写出主动舍弃清单及原因。至少检查是否可以只用一个案例完成全文；默认不要求“一个主经历加一个辅助经历”。
5. 从目标专业反向检查：删除学校名、专业名和最后一段后，正文是否仍然自然指向该领域。若不能，重新设计证据链。

## 经历复用审计

同一经历出现在其他目标 PS 时，不得直接重写旧段落。写作前先检索其他最新正式 PS 中所有涉及该经历的段落，并为本篇建立“语义增量卡”：

- 不可变事实：项目名称、时间、角色、真实数据、真实结果等可以重复但不得改写含义。
- 本篇核心问题：这次用该经历回答什么专业问题。
- 本篇选取片段：只选择与核心问题有关的一个阶段、决策、矛盾、结果或细节。
- 本篇行动焦点：申请人具体做了什么判断、取舍、分析或协调。
- 本篇约束：当时真正限制决策的事实是什么。
- 本篇能力结论：该经历在本篇证明的能力、判断或成果；确有相关边界时再说明，不要求每项经历都暴露不足。
- 主动省略：旧稿已经充分使用、但本篇没有独立价值的事实、数据、方法和结果。
- 禁止复用：旧稿的完整非事实句、相同事实组合、相同行动链和相同反思结论。

同一经历再次进入正文，至少应在以下五项中产生三项实质变化：选取片段、核心问题、行动焦点、约束、能力结论。更换专业术语、调换句序、替换同义词或把同一反思连接到不同课程，不算变化。

必要硬事实可以重复，但只保留完成本篇论证所需的最小事实核。不得每次都从项目背景讲起，再完整复述“任务—方法—数据—结果—反思”。如果找不到新的真实片段或新的论证职责：

1. 优先舍弃该经历。
2. 如因背景连续性必须提及，压缩成一句事实引用，不再展开为完整经历段。
3. 不得依靠想象补出新的冲突、动作或结果来制造差异。

同一经历可在一篇中作为主案例，在另一篇中只作为反例、边界证据或简短背景；不要求每次都获得相同篇幅和完整叙事。

## 篇章架构

应届生 PS 仍需覆盖本科专业选择、本科经历、职业规划、硕士专业与学校选择原因，但这些是信息责任，不是固定顺序、固定段落或固定篇幅。只要因果链清楚，可以前置能力缺口、让职业问题成为开头、把本科选择嵌入经历反思，或将 Why Program 分散连接到不同学习需求。

根据本篇核心命题自然决定架构。可参考但不得轮流套用以下论证路径：

- 问题演化：具体问题或判断 → 尝试与修正 → 认识变化 → 新能力缺口 → 学习选择。
- 单案例深挖：一个案例贯穿全文 → 决策与约束 → 结果或反思 → 能力边界 → 下一步。
- 对照论证：两个经历产生不同认识 → 比较差异 → 形成专业判断 → 学习与职业方向。
- 职业倒推：目标工作中的问题 → 已有能力证据 → 缺失能力 → 为什么此时申请。
- 学术问题推进：课程或分析问题 → 实践检验 → 理论边界 → 深造需求。

架构名称只用于内部设计，不写入正文。不得为了制造差异机械选择架构；真正的差异来自核心问题、因果关系和素材取舍。

允许 4–7 段或申请题目要求的其他段数。禁止默认生成统一六段式，尤其不得让所有申请目标都采用“专业化钩子→GPA背景→主经历→辅助经历→职业目标→Why Program”。GPA、院校和本科专业可以嵌入最需要它们的论证位置，不得自动形成固定第二段。

段落篇幅由论证权重决定，不按经历平均分配。核心案例可以占据明显更大篇幅，边界证据可以只有一两句，弱辅助经历应删除。不得把每项经历都加工成长度接近、内部都采用“背景→行动→结果→反思”的标准段落。

段落内部也应有节奏差异：可以从决策、矛盾、结果、观察或能力边界进入，不要每段都先介绍项目背景。篇幅变化必须来自信息密度和论证职责，不为制造表面差异随机拉长或缩短。

## 五个差异化决策

每篇写作前明确以下决策，并与已有 PS 横向比较：

1. **开头切入**：从本篇独有的核心问题选择因果起点。不得只是给同一经历换一个观察句。
2. **学术背景**：只有当 GPA、学校或课程能够证明学习准备度、解释转向或支撑能力缺口时才写。默认压缩并嵌入相关论证；除非学术轨迹本身是主线，不单设完整背景段。
3. **辅助经历**：没有提供新证据、新约束或反例的经历必须舍弃。不得为了覆盖简历而补齐第二或第三项经历。
4. **职业目标**：由本篇真实经历、已体现的能力、专业判断或已明确的兴趣自然推导，解释希望承担的工作与学习需求；不得复用统一的短期/长期目标句式后替换岗位名称。
5. **Why Program 功能**：根据本篇因果链承担一种主要职责，例如解决明确能力缺口、提供验证假设的场景、完成职业转向、深化已有方法或整合此前分散能力。可以融入前文或用于收束，但不得每篇都以“该项目是下一步”加课程列表结尾。

这些功能不是新的模板库。组合中要避免相同结尾动作：有的稿件可收束于尚待解决的问题，有的可说明新的决策标准，有的可连接职业任务，有的可回扣开头，但必须由正文逻辑自然产生。

## 专业簇与组合约束

同一学生有多个目标时，先按相近问题建立专业簇，再做簇内差异化。专业簇用于识别最容易同构的近邻项目，不意味着同簇共享底稿。

- 相邻项目之间至少改变以下五项中的两项：因果入口、素材取舍、经历职责、能力缺口出现位置、职业目标生成路径或结尾论证方式。
- 相邻项目不得同时复用相同主证据、相同辅助证据、相同段落位置和相同能力结论。
- 同一结构签名原则上最多用于两个目标；使用两次时，证据选择和结论路径必须显著不同。
- 同一经历在三个及以上目标中出现时，不得反复承担同一职责或导出同一能力结论。
- 组合中不得所有 PS 都使用相同段数、固定 GPA 段、固定职业规划段和固定 Why Program 末段。
- 必须保留必要硬事实，不为降低相似度机械改写 GPA、院校、项目名称或数据。

## 成文规则

成文必须同时满足五维质量标准：英文语言质量、结构与逻辑主线、素材/细节与反思深度、专业与项目匹配度、个人辨识度与申请说服力。

- 使用学生第一人称。
- 输出为同一 `.md` 文件内的双语版本：先输出英文正文，再输出中文正文。
- 英文正文是正式申请稿，应使用成熟、自然、学术但不堆砌的英语表达。
- 英文正文默认控制在 700-1000 words，目标长度约 800 words；如果项目官方明确要求其他范围，以项目要求为准并在任务输入中记录覆盖值。低于适用下限或高于适用上限时，不得作为正式候选稿通过。不为凑字数牺牲事实准确性和逻辑密度，但应通过补足已确认事实的论证、行动焦点、能力边界和项目匹配来达到适用下限。
- 中文正文紧随英文正文之后，用于对照理解；内容应与英文一致，但不要求逐字直译。
- 英文和中文都必须是逻辑连贯的文章，不要分点，不要列清单，不要写成提纲。
- 不需要把所有经历都写进去，只选择与申请专业最相关、最能支持主线的经历。
- 允许只深挖一个经历；不得为了“内容完整”自动补入第二个项目。
- 围绕申请专业建立清晰主线：兴趣来源、能力积累、课程/项目/实习证据、职业目标、项目匹配。
- 多专业申请时，目标专业必须影响全文的核心问题、素材排序、经历解释和能力结论，不能只影响职业目标与 Why Program。
- 不同目标 PS 的首段不得复用完整的非事实句；前两段不得同时采用相同开头、相同经历顺序和相同能力结论。
- 不同目标 PS 的首段不得以相同的非中性模板重复同一叙事动作；兴趣来源、问题、异常或场景等类别名称本身不构成判错依据，须比较实际句式、信息入口与论证功能。生成前和审查时必须记录“开头原型、第一段动作、第二段证据职责”，不能只记录专业主题。
- GPA、院校、本科专业等硬事实可以重复，但不得让同一组背景事实长期占据每篇 PS 的相同开头位置和相同篇幅。
- 同一项目可以复用事实，但必须改变其在论证中的功能和反思重点；仅替换专业关键词、同义词或课程名称不构成差异化。
- 同一项目再次使用时，必须完成经历复用审计；不得复用相同事实包、行动链和反思结论。
- 每段必须承担与核心命题有关的具体论证职责，例如提供证据、说明行动、解释判断或连接学习需求，不得只是填充“背景”“主经历”“辅助经历”“规划”“项目匹配”等预设槽位。
- Why Program 不得成为不同项目 PS 的唯一差异区域。
- 优先使用具体课程、项目、实习、科研、竞赛或问题解决经历，避免空泛形容。
- 如果课程、推荐人、个性化或简历素材中提到 PDF、PPT、DOCX 等附件文件名，必须查找并读取 `Additional_Documents/同名.md`；附件内容只作为事实依据补充，不得替代或扩大原始学生资料。
- `Personalization_Materials/` 中标为“已确认事实”的内容可作为正文事实依据；标为“合理推断/表达方向”的内容可用于构建具体但面向未来的转向动机与职业规划，遵循上文“未明确的转向动机与职业方向”；标为“待确认”的过去或现在的事实不得写成确定事实。
- 如果 `Student_Profile/学生偏好总结.md` 与 `Personalization_Materials/` 冲突，按以下规则处理：过去或现在的事实以可追溯资料和用户最新明确输入为准；表达风格以学生偏好总结为准；无法判断的关键事实保留 `[待确认：...]` 或进入 `Blocked`，不要自行裁定。仅缺少对未来转向动机或职业方向的明确陈述，不属于此处的关键事实冲突。
- 如果申请学校/项目细节不足，且 `Major Selected/` 中没有可用信息，不编造课程名、教授名或实验室名，用自然句提示信息不足，或在草稿中保留 `[待补充：项目匹配信息]`。
- 不伪造数据、奖项、排名、项目成果、公司名称、课程名称或时间节点。
- 注意经历时间线，不可出现本科、实习、课程、未来规划顺序错乱。
- 语言应成熟、具体、连贯，英文避免中式直译和过度夸张，中文避免机械翻译腔。
- 根据学生偏好总结调整语气、详略和表达风格。
- Why Program 不得罗列课程。通常只展开 2–3 项最相关资源，并分别说明其对应的既有经历、具体学习需求和未来用途。
- 默认不得写入 4 门及以上具名课程。若学校题目明确要求讨论多门课程，只有在每门课程都有实质关联分析时才可例外；不得通过把课程列表改写成长句来规避本规则。

## 句式与信息组织

每篇初稿在事实与论证内容确定后、送事实审查前，必须按 [全文句式与信息组织重构.md](references/全文句式与信息组织重构.md) 完成一次主动的全文重构。先通读、记录各段主句骨架与信息层级，再按关系组织背景、行动、判断和未来意向，最后核对语义、双语及词数。不得只抽查首尾、消除语法错误或替换重复开头。

即使每句事实不同，全文持续采用“I 做了—I 学到—I 希望”的平铺骨架也需要处理。主动运用指南中的主从句、非谓语、同位语、对照及具体对象承接，让重点、条件和背景有层级；让短句突出判断、较长句承担关系。不设句法配额，但不得以“简单句自然”免除全文丰富度检查；I hope 换成 I aspire 不算完成。

保留有效简单句、个人行动与准确指代；不为变化虚构因果、失败、顿悟或深造需求，不把未来愿望写成承诺。内部全文诊断只留在任务临时目录，不进入正文或下一轮盲审输入。

## 复核流程

输出前必须自查并修正：

1. 文章是否履行本科选择、经历、职业方向和硕士选择的信息责任，同时由本篇核心命题决定因果顺序。
2. 正文是否包含英文在前、中文在后的双语版本，且两版都没有分点列举。
3. 所有过去和现在的事实是否能在用户资料或申请项目信息中找到依据；写作者构建的未来动机与职业规划是否有合理因果支撑，且未被表述为已确认的既成事实。
4. 是否出现伪造数据、伪造经历、伪造课程、伪造学校项目信息。
5. 是否把 `Personalization_Materials/` 中待确认的经历或既成决定误写成已确认事实；是否因缺少未来意向原话而不必要地阻塞。
6. 按时间表达参考逐项核对正文与内部来源：年级换算、暑期前后、跨学年区间、实际进度、未来/完成状态及双语是否一致；无必要个人日期和预计毕业句是否已省略，保留日期是否有明确理由。
7. 是否使用了与申请专业最相关的经历，而不是堆砌全部素材。
8. 英文版与中文版事实是否一致，中文是否只是对照稿而非另起一篇不同事实的文章。
9. 英文正文是否处于适用字数范围：默认 700-1000 words、目标约 800 words；若项目有官方覆盖值，是否已记录来源；低于下限或高于上限必须返修。
10. 是否按五维质量标准逐项完成内部自查，尤其检查英文地道性、主线、经历反思、课程相关性和个人辨识度。
11. 是否完成课程堆砌检查：统计具名课程数量，检查是否连续罗列、是否占据 Why Program 主要篇幅，以及每门课程是否连接既有经历、具体学习需求和未来用途。
12. 是否已读取同一学生其他目标项目的最新 PS，并完成申请组合叙事矩阵。
13. 是否出现“前文基本相同，只改职业目标和 Why Program”的情况。
14. 是否形成了可解释的结构签名；GPA、职业规划和 Why Program 是否再次占据与其他稿件相同的固定位置。
15. 是否记录了主动舍弃素材，正文是否仍在无必要时使用“主经历 + 辅助经历”的默认组合。
16. 相邻专业是否至少改变了两项关键设计维度，同一经历是否再次导出近似能力结论。
17. 复用经历是否有语义增量卡，是否至少改变选取片段、核心问题、行动焦点、约束、能力结论中的三项。
18. 各经历段是否被平均分配成相近篇幅和相同内部结构；弱证据是否应该压缩或删除。
19. GPA/学校背景是否确有论证价值，职业目标是否由本篇问题推导，Why Program 是否承担与其他稿件不同的收束功能。
20. 对候选稿运行 `Application_System/tools/check_ps_portfolio_similarity.py`；必须查看文字相似度、`rhetorical_signature`/`structural_similarity`、`experience_passage_similarity`、`opening_template_family` 和 `opening_template_family_overlap`。若状态为 `Needs Differentiation`，结合矩阵重构经历内容、因果路径或素材取舍，不能只做同义改写。
21. 完成“矩阵四层约束自检”：事实与经历职责、核心问题、叙事动作与段落结构、思维人格与结尾姿态均须有正文证据；任一层不通过，候选稿不得进入正式发布。
22. 是否完成覆盖每一段的全文句式与信息组织重构，能否从经历主体及动机/项目/职业段说明主从安排、信息承接与节奏的实质变化或保留理由；是否只是换开头、改 hope 同义词，或用另一种统一高级句式替代旧模板。

如果发现无法核实的过去或现在的事实，应删除、弱化，或改为 `[待补充：...]`；对未明确的未来转向动机和职业方向，按上文规则构建，不自动留占位符。
如果最终正文仍包含 `[待补充：...]`、`[待确认：...]` 或类似占位符，该版本不得作为 `Pass` 交付稿，只能作为待补充草稿进入 `Needs Fix` 或 `Blocked`。

## 输出

保存到 `Personal_Statement/`：

- `.md` 成稿，英文在前、中文在后，保存在同一个文件中

命名规则：

- 文件名必须带版本号 `Vn`。
- 文件名不得添加日期前缀。
- 生成前扫描 `Personal_Statement/` 中同一学生、同一目标专业/学校的历史 PS，取最高版本加 1。
- 可用 `Application_System/tools/next_version_path.py` 生成路径。
- 该 `Vn` 是本次任务唯一预留的正式交付版本。写作和审查期间使用临时 `R1`、`R2` 等候选稿；全部审查通过后才把最终候选稿保存为该 `Vn`，并只向用户展示这一版。

示例：

`学生名-目标专业-Personal-Statement-V1.md`

## 阻塞条件

- 缺少学生身份、教育背景、申请专业或目标方向，导致无法建立事实主线。
- `Personalization_Materials/` 为空且现有资料不足以生成安全的补写候选。
- 申请项目细节必须具体匹配，但用户未提供目标学校/专业信息。
- 资料之间存在关键事实冲突，且无法从来源或用户最新输入判断。

## 最小输出

- `Personal_Statement/` 下唯一的新正式版本 `.md`；内部候选稿不得进入该目录。
- 调用 `application-review`；内部报告只写任务临时目录，全部门禁通过并发布正式 `Vn` 后才生成对应 `Review_History/` 最终审查报告。
- `application-review` 为 `Pass` 后，由全新隔离 Subagent 调用 `external-application-review` 做八维内容审稿：前七维在初始单篇 `C1-C5` 检查，第八维在独立组合 `P1-P5` 检查。即使初始单篇到 `C5` 才通过，也必须另行执行组合 `P1`，不得因单篇上限耗尽而跳过。单篇或组合低于 `8.5`、或存在 P0/P1 时，主控 Agent 制作净化交接包，由另一个全新隔离修改 Subagent 生成下一个内部 `Rn`，再调用 `application-review`；组合触发的修改还须由全新隔离审稿人执行补充单篇复核 `S1-S5`，通过后再进入下一 `Pn`。`C`、`S`、`P` 独立计数，正式 `Vn` 始终不变。
- 审稿人只读取当前候选稿和最小项目摘要；修改者只读取当前候选稿、净化问题单和最小事实包。旧稿、逐轮得分、完整历史报告和过程推理不得跨 worker 流转。
- 有其他目标项目 PS 时，必须完成 `external-application-review` 的独立 `P1-P5` `portfolio-differentiation` 隔离审稿；只有当前候选的事实、单篇和组合门禁均 Pass 才发布。
- 创建或更新 `Student_Profile/PS_申请组合叙事矩阵.md`。
- 必要时更新 `Student_Profile/Task_Board.md`。
- 如果使用或生成了个性化素材补写候选，保留在 `Personalization_Materials/`。
