# Student Style Memory

## 使用场景

当完成文书修改、用户明确总结偏好、或写作前需要读取学生长期风格偏好时使用。

## 记忆文件

每个学生目录下维护：

`Student_Profile/学生偏好总结.md`

## 参考资料

- 本 skill 的参考文档放在 `Application_System/skills/student-style-memory/references/`。
- 可放偏好总结样例、风格标签说明、反馈归类规则、禁用表达沉淀规则等。
- 更新偏好前如参考目录中有与当前反馈类型或文书类型相关的文件，应优先读取相关文件；不要无差别读取全部参考资料。

## 记忆结构

文件应包含：

- 稳定偏好
- 待观察偏好
- 推荐信偏好
- 个人陈述偏好
- 简历偏好
- 禁用或慎用表达
- 常用核心素材
- 历次修改摘要

## 更新规则

- 修改后自动更新。
- 明确、重复或强烈反馈写入“稳定偏好”。
- 单次、模糊或可能只针对某篇文书的反馈写入“待观察偏好”。
- 不把一次偶然意见泛化到所有文书类型。
- 保留日期、文书类型和反馈来源，方便回溯。
- 只记录学生个人偏好、风格偏好、素材偏好和禁用表达。
- 不记录审查发现的事实错误、版本问题、素材混用、模板残留、结构错误或流程错误；这些内容写入 `Review_Memory/审查问题记忆.md`。
- 不把 `Personalization_Materials/` 中的“合理推断/表达方向”直接沉淀为稳定偏好。
- 个性化素材中的内容主线应继续保留在 `Personalization_Materials/`；只有用户明确表示喜欢某种表达、详略或风格，或多次修改体现同一偏好时，才写入学生偏好总结。

## 通用化门禁

每次从批注、审稿报告或修改结果中沉淀个人偏好前，必须先执行“通用化门禁”。只有通过门禁的内容才能写入 `Student_Profile/学生偏好总结.md`。

1. 先抽象修改意图，而不是复制具体专业内容。应从“为什么改”中提炼可迁移原则，例如“减少工具名堆叠，突出判断链条”，而不是写成“机器人文书要突出机械-控制耦合”。
2. 判断适用范围。若规则只适用于某一专业、某一项目、某一经历或某一学校，不得写入通用偏好；最多写入对应文书类型下的“待观察偏好”，并明确限定适用范围。
3. 删除专业限定例子。偏好总结中的规则不得依赖特定专业术语才成立。可以写“具体项目问题、异常现象或实践场景”，不要写“机器人失效/机械-控制耦合/AI 与物理系统”等会误导其他专业的例子，除非明确标注“仅限 Robotics/MAE/AI4Science 方向”。
4. 通过反例测试。写入前问：如果下一个目标是商科、教育、传媒、公共政策、纯数据科学或其他非当前专业，这条偏好是否仍然有帮助且不会误导？若答案是否，则不要作为通用偏好写入。
5. 保留事实边界。若内容是“学生有什么经历、某段素材可以怎么用”，写入 `Personalization_Materials/` 或“常用核心素材”；若内容是“不要再犯某类写作/审查错误”，写入 `Review_Memory/审查问题记忆.md`。

通过门禁后的偏好应写成中性表达：

- 推荐：`经历段宜突出“问题识别—判断依据—行动取舍—能力结论”的链条；技术名词、课程名、工具名和硬件型号只在服务论证时保留。`
- 不推荐：`个人陈述宜突出机器人工程实践中的系统判断，如机械-控制耦合、机器人闭环、电子接口、AI 与物理系统。`

## 归类路由

从一次修改中得到的结论必须按以下路由归档：

| 结论类型 | 写入位置 | 示例 |
|---|---|---|
| 学生明确喜欢/不喜欢某种表达、语气、详略或结构 | `Student_Profile/学生偏好总结.md` | 学生偏好具体问题开头；不喜欢过度抒情 |
| 从批注中抽象出的跨专业写作原则 | `Student_Profile/学生偏好总结.md` 的对应文书类型偏好或待观察偏好 | 经历段避免清单化，优先写判断链条 |
| 专业限定的写法、某项目专属叙事策略 | `Student_Profile/PS_申请组合叙事矩阵.md` 或对应修改总结 | MAE 首段用机械-控制故障入口 |
| 审稿发现的错误模式、模板残留、版本问题、素材混用 | `Review_Memory/审查问题记忆.md` | 多篇 PS 不应共享同一非中性开头模板 |
| 学生事实素材、可用经历细节、待确认事实 | `Personalization_Materials/`、`Resume/`、`Course_Info/` 等素材目录 | 山东蒙德实习可用内容与仍需确认的设备型号 |
| 只对本次文书有效的修改过程 | `Revision_History/` | 本次从 V2 到 V3 只做 copyedit |

若同一条反馈同时包含多个类型，应拆分归档，不得整段塞入偏好总结。

## 写入格式要求

- 每条偏好必须包含日期和来源，例如“根据 Robotics PS Word 批注反馈”或“根据用户明确反馈”。
- 每条偏好应尽量使用专业中性的词，如“项目问题”“实践场景”“工具/方法名”“目标领域术语”“能力结论”。
- 若必须保留专业限定，必须在句首标注范围，例如“仅限 Robotics/MAE 方向：...”。
- 不得把 `Review_Memory` 中的错误模式原样复制到学生偏好总结；应先抽象成正向、通用、不会误导其他专业的写作偏好。

## 写作前使用

写作或修改前先读取学生偏好总结，并遵守：

- 禁用表达优先级最高。
- 文书类型偏好优先于通用偏好。
- 待观察偏好作为参考，不作为硬规则。

## 阻塞条件

- 无法判断某条结论属于学生偏好还是审查问题时，先不要写入稳定偏好。
- 反馈只体现单篇文书内容事实，而非长期表达偏好时，不写入学生偏好总结。
- 无法把某条批注意见抽象为跨专业可用原则时，不写入学生偏好总结；将其写入 `Review_Memory/审查问题记忆.md`、`PS_申请组合叙事矩阵.md` 或对应素材目录。

## 最小输出

- 更新或确认 `Student_Profile/学生偏好总结.md`。
- 必要时在修改总结中说明哪些反馈未沉淀为长期偏好。
